# Marketing Brain (ชั้น Decision แบบมีกฎ)

หน้าใช้งาน: `/system/marketing/` (ลิงก์จาก HQ เมนู "Marketing Brain ↗") ต้องล็อกอินแอดมินเหมือนหน้าอื่น
API: `GET /api/marketing-brain`, `POST /api/marketing-brain` (ตั้งค่า), `GET/POST/DELETE /api/ad-spend`
โค้ดกฎทั้งหมด: `shared/marketing.js` (ฟังก์ชันล้วน ทดสอบได้) เทสต์: `tests/marketing*.test.mjs`

## หลักการ
- สรุปหลักฐานและ **แนะนำ** เท่านั้น คนเป็นผู้ตัดสินใจ ไม่มีการลงมือเอง และไม่ใช้ AI (ต่อทีหลังเมื่อมีข้อมูลจริงพอ)
- นับเฉพาะข้อมูลจริง: ไม่รวมออเดอร์/เหตุการณ์/lead ที่ติดป้ายทดสอบ และไม่รวมออเดอร์ที่ยกเลิก
- ไม่ตัดสินจากข้อมูลน้อย: ต้องมีอย่างน้อย `min_sessions` (เริ่มต้น 50) เซสชัน ยกเว้นกฎกันเงินรั่ว (STOP)

## สถานะที่ระบบแนะนำ
| สถานะ | เงื่อนไข (ช่องที่มีค่าโฆษณา) |
|---|---|
| STOP | ใช้ถึงงบทดสอบ (เริ่มต้น 1,500 บาท) แล้วยังไม่มีออเดอร์ที่จ่ายแล้ว (ไม่ดูจำนวนเซสชัน) |
| INSUFFICIENT_DATA | เซสชันน้อยกว่า min_sessions |
| FIX | เซสชันพอ แต่ไม่มีออเดอร์ที่จ่ายแล้ว: ห้ามเพิ่มงบ ตรวจข้อเสนอ/หน้าสินค้า/ขั้นตอนชำระเงิน |
| SCALE | กำไร÷ค่าโฆษณา >= 2 และมีออเดอร์ >= 3: เพิ่มงบทีละไม่เกิน 20% |
| KEEP | กำไร÷ค่าโฆษณา 1-2 หรือออเดอร์ยังน้อย: คงงบ |
| REDUCE | กำไร÷ค่าโฆษณา < 1: ลดงบหรือแก้ข้อเสนอ |
ช่องฟรี (ไม่มีค่าโฆษณา): WORKING (มียอด) / NO_SALES_YET (มีคนเข้าแต่ไม่มียอด) ส่วน `(direct)` คือไม่ทราบช่องทาง ไม่มีคำแนะนำ

## สูตร
- กำไรขั้นต้น = รายได้ที่จ่ายแล้ว − (กก. × ต้นทุนต่อ กก.) − (ออเดอร์ × ต้นทุนอื่นต่อออเดอร์)
- ต้นทุนต่อออเดอร์ (CAC) = ค่าโฆษณา ÷ ออเดอร์ที่จ่ายแล้ว · กำไร÷ค่าโฆษณา = กำไรขั้นต้น ÷ ค่าโฆษณา
- **ค่าเริ่มต้นเป็นสมมติฐาน:** ต้นทุน 390 บาท/กก. และต้นทุนอื่น 0 บาท ต้องตั้งค่าให้ตรงความจริงที่หน้า (ยืนยันว่า 390 คิดต่อเมล็ดสารหรือเมล็ดคั่ว) ไม่งั้นกำไรจะสูงเกินจริง ระบบแสดงคำเตือนจนกว่าจะตั้งค่า

## วิธีใช้
1. ทุกลิงก์ที่แจก/ยิงโฆษณาต้องมี `?src=ช่องทาง` หรือ `utm_source=ช่องทาง` (เช่น `?utm_source=facebook&utm_medium=paid&utm_campaign=launch`) Meta/Google/TikTok ที่ไม่มี utm ระบบเดาจาก fbclid/gclid/ttclid ให้
2. ใช้ลิงก์ `?src=` ช่องทางเดียวกับที่บันทึกค่าโฆษณา (ชื่อช่องทางต้องตรงกัน: fb = facebook อัตโนมัติ)
3. บันทึกค่าโฆษณารายวันที่หน้านี้ แล้วดูคำแนะนำทุกสัปดาห์ ปรับทีละช่องทาง
4. ตั้งค่าที่ท้ายหน้า: ต้นทุนต่อ กก., ต้นทุนอื่นต่อออเดอร์, เป้า กก./เดือน, กำลังคั่ว

## แก้ที่เกี่ยวข้อง (ทำพร้อมกัน)
- `src/App.tsx` `saveUtm()`: เดิมบันทึกช่องทางเฉพาะเมื่อมี `utm_source` ทำให้ลิงก์ `?src=facebook|line|gbp` ใน HANDOFF ไม่ถูกส่งไปกับออเดอร์ ยอดจึงขึ้นเป็น "(direct)" ตอนนี้ใช้ `src` (หรือ fbclid/gclid/ttclid) เป็น utm_source สำรอง ผลใช้กับผู้เข้าเว็บหลัง deploy เท่านั้น
- เซสชันของช่องทาง = จำนวน session_id ที่เปิดหน้าร้านจากช่องทางนั้น (event `content_view`) ส่วนเหตุการณ์เก่าที่มีแค่ `src` ระบบอ่านจาก `src` ให้

## ข้อจำกัดที่ควรรู้
- ออเดอร์นับช่องทางตามที่ติดมากับ session ล่าสุดที่มี utm (last-touch ในเบราว์เซอร์นั้น) ถ้าลูกค้าเห็นโฆษณาแล้วกลับมาพิมพ์ URL เอง ยอดจะไปอยู่ช่องทางเดิมถ้า localStorage ยังอยู่ แต่ถ้าเปลี่ยนเครื่อง/ล้างข้อมูล จะเป็น (direct)
- ออเดอร์จากแชท LINE ที่ลูกค้าสั่งผ่านการคุยตรง (ไม่ผ่านเว็บ) ไม่ถูกนับในระบบนี้
- ยังไม่มีการวัดแยกตามแคมเปญ/ครีเอทีฟ (ดูระดับช่องทางก่อน)
- Meta Pixel / Google tag ยังไม่ได้ติด ต้องผ่านการตรวจ PDPA ก่อน (ดู `docs/TRACKER-PDPA-REVIEW.md`)
